# Task 3.5 — Acceptance Criteria (Given-When-Then)

Business rules (credit norms, hour limits, profession-oriented and free-choice limits) come from the ІНП planner context.

For EACH story, write Gherkin scenarios:
1. At least 1 Happy Path and at least 1 Edge Case or error.
2. For edge cases, consider: boundary values (exactly at a limit, one above it), an empty state, duplicates, an unauthenticated user, decimal credits (e.g. 3.5), and courses that run over several semesters.
3. Use concrete data (course names, numbers) and a result the user can see or a tester can check. Don't describe implementation (no API, DB or tool names).
4. Each scenario tests one behaviour and is independent of the others.

Output (Markdown), grouped by journey step:

### US-X.Y — <short story title>
```gherkin
Scenario: <name>
  Given ...
  When ...
  Then ...
```

At the end: a list of `[TBD]` items the team must confirm.
