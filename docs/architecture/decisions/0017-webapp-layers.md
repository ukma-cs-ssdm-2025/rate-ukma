# ADR-0017: Webapp Layers Enforced by Lint

## Status

Accepted

## Date

2026-11-21

## Context

The webapp (`src/webapp/src`) has four kinds of folders: `routes/` (TanStack file routes), `features/<name>/` (one product area each), `components/` (shared UI) and `lib/` (shared non-UI code, including the generated API client). Nothing enforced how they depend on each other, and the code drifted:

- Routes hold page logic. 7 of 18 route files call generated API hooks, and `routes/courses.$courseId.tsx` is 301 lines.
- Shared code reaches into features. `components/Header/Header.tsx` and `Header/MobileMenu.tsx` import from `features/notifications`; `components/AuthShell.tsx` and `components/TermBadge.tsx` import `features/courses/courseFormatting`.
- Features import each other in a cycle: `courses` renders `feed`, and `feed` imports course formatting from `courses`.
- Files grow large: `CourseFiltersPanel.tsx` has 860 lines, `RatingComments.tsx` 835, `CoursesScatterPlot.tsx` 792, `CoursesTable.tsx` 733, `RatingForm.tsx` 597.
- Two barrel files (`lib/auth/index.ts`, `lib/feature-flags/index.ts`) re-export modules, so imports do not say where code lives.

A rule written only in `AGENTS.md` does not stop the next change from breaking it. Fixing every offender in one change is too large to review and every webapp merge deploys to live.

## Decision

We will keep four layers, each allowed to import only the ones below it:

1. **`routes/`** is thin: it reads params, applies the auth guard and the head/title, and renders one `<XPage>` from its feature. It may import generated API types, never generated hooks.
2. **`features/<name>/`** owns its pages, components and hooks. Feature hooks are the use cases: there is no separate use-case or service layer, and components call generated hooks directly unless a hook adds behaviour (see `src/webapp/AGENTS.md`). A feature imports another feature only along a declared, acyclic dependency graph (`FEATURE_DEPENDENCIES` in `src/webapp/lint/layers.ts`).
3. **`components/`** is shared UI and **`lib/`** is shared code. Neither imports `features/` or `routes/`; a shared component that needs feature content takes it as a prop or slot.
4. **`lib/api/generated/`** is generated by orval and never edited.

Every source and test file stays under 400 lines, and there are no barrel `index.ts` files (route files named `index.tsx` are TanStack routes, not barrels).

Lint enforces all of it:

- oxlint (`src/webapp/oxlint.config.ts`): `import/no-cycle`, `max-lines` (400), and `no-restricted-imports` overrides per folder, generated from `lint/layers.ts`.
- `pnpm lint:ratchet` (`scripts/lint-ratchet.ts`, part of `pnpm check`): every folder in `features/` is declared in `FEATURE_DEPENDENCIES`, the declared graph has no cycle, and no `index.ts` barrel exists.

Today's offenders are listed in `src/webapp/lint/allowlist.ts`, which may only shrink. The ratchet fails when an allowlisted file no longer breaks its rule, so the entry has to be removed in the change that fixes it. Adding an entry is not allowed; a new file follows the rules from its first commit.

## Consequences

- ✅ The layering is checked on every `pnpm check`, locally and in CI.
- ✅ Each fix shrinks the allowlist, so progress is visible in one file.
- ✅ Routes become a readable map of URLs to pages, and page logic is tested with its feature.
- ⚠️ An allowlisted file is exempt from its whole rule, not from one import, until it is fixed.
- ⚠️ A new cross-feature import needs an edit to `FEATURE_DEPENDENCIES`, which reviewers should question.
- ❌ Moving shared helpers out of a feature (for example course formatting into `lib/`) touches many imports at once.

## Considered Alternatives

1. **A separate use-case (application) layer between components and the API client**
   - Rejection Reason: generated React Query hooks already are the data layer. A wrapper per call only renames hooks, which `src/webapp/AGENTS.md` already forbids.
2. **dependency-cruiser or eslint-plugin-boundaries**
   - Rejection Reason: a second linter and config for rules oxlint's built-in `no-restricted-imports` and `import/no-cycle` express, plus a short script for the feature graph.
3. **Fix every offender before turning the rules on**
   - Rejection Reason: one change of several thousand lines that deploys to live on merge. The allowlist lets the rules guard new code now and the fixes land in small reviewed steps.
