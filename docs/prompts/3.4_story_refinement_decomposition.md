# Task 3.4 — MVP Story Refinement & Decomposition

Input: the In Scope (MVP) stories from task 3.3, section 2. Work ONLY with these stories. Don't add new scope.

For each story:
1. **Check the format** "As a [who], I want [what], so that [why]":
   - **who:** a specific role (planner, contributor, data maintainer, developer), not "user" or "team".
   - **what:** one action the user can see, with no implementation details (no Sentry, worker or API names).
   - **why:** a real value or outcome, not a rephrased "what".
2. **Check atomicity:** if a story mixes two separate actions (e.g. "add and remove", "view and edit"), split it into independent stories. Each new story must deliver value on its own and be testable separately.
3. Keep the original IDs. Split stories get suffixes: US-5.10 → US-5.10a, US-5.10b.

Output (Markdown):
- **Changes table:** `Original ID | Problem found (format / atomicity / none) | What changed`
- **Final MVP stories:** `ID | Step | Story`, grouped by journey step. These are the stories that go to the Acceptance Criteria step.
