# Task 4.1 — Requirements Digest

## Role
You are a systems analyst. Turn our MVP requirements into a short technical
digest that developers will use to design the data schema and API.

## Inputs
- `docs/requirements/requirements.md`
- `docs/requirements/story_mapping_scope.md` — MVP boundary is defined here
- `docs/requirements/story_enhance.md`
- `docs/requirements/acceptance_criteria_gherkin.md`
- `docs/product-discovery/summary.md` — persona and context

## Output
Write `docs/requirements/requirements-digest.md`. Keep it short: tables and
diagrams only, no introductions, no explanations, no repeated information.

### 1. Entities
Table: Entity | Definition (one line) | Key attributes | Relationships (with cardinality)

### 2. Lifecycles
For each entity that changes state:
- Mermaid `stateDiagram-v2` with all states and transitions
- Table: From → To | Trigger (who/what) | Condition
- One line listing forbidden transitions
If an entity has no states, do not include it here.

### 3. Business rules
Table: ID | Rule (one sentence) | Source story ID

### 4. Prohibitions
What the system must never do or allow.
Table: ID | Prohibition ("The system must never…") | Source story ID

### 5. Technical assumptions for MVP
Table: ID | Assumption (one sentence)
Must cover: authentication method, ID format, course data source,
time zone / dates, what is out of scope for MVP.
