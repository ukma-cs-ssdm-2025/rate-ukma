# Task 4.2 — ADR Generation

## Role
You are a software architect on a student team. Record only the architectural
decisions that our MVP forces us to make. Base decisions are already recorded.

## Inputs
- Existing ADRs: `docs/architecture/decisions` — read all of them first
- Existing code: `src/backend/`, `src/webapp/` — to see the current stack
- `docs/requirements/requirements-digest.md` — entities, lifecycles, rules
- `docs/requirements/results/story_mapping_scope.md` — MVP boundary

## Team constraints
- Team: 5 people in three tracks: ІНП planner (2), САЗ parser (2), analytics (1)
- Deadline: 30.11
- Runs locally only, no paid services, zero budget
- The existing product (sign-in, catalog, ratings, reviews) already works
  and must not be rewritten

## Task
1. List the decisions already covered by existing ADRs (one line each).
2. Pick exactly 2 new decisions that MVP stories require and existing ADRs
   do not cover. Choose the ones with the highest impact on the schema or API.
   Candidates to consider: how an ІНП plan is stored, where credit/hour
   rules are validated (backend, frontend or both), how parser data refresh
   and correctness checks work.
3. Write each decision as a separate file:
   `docs/architecture/decisions/NNNN-short-title.md`, continuing the existing numbering.

## ADR format (keep each under one page)
- **Status:** Proposed
- **Context:** 2–3 sentences: what forces the decision, which stories (IDs)
- **Options:** table: Option | Pros | Cons | Fits constraints (yes/no + why)
  At least 2 options, at most 3.
- **Decision:** one sentence
- **Consequences:** 2–4 bullets, including what becomes harder

## Rules
- Do not repeat or contradict existing ADRs. If an MVP need conflicts
  with one, say so in Context instead of reversing it silently.
- Every option must be realistic for this team, deadline and zero budget.
- No generic text: each ADR must name our entities and stories.
- Before writing files, show the list from step 1 and the 2 chosen decisions
  with one-line reasons, and wait for my confirmation.
